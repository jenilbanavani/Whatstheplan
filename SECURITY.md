# Security Policy

## Reporting Security Vulnerabilities

We take the security and privacy of our users seriously. 

If you discover a security vulnerability or privacy concern in **What's the Plan?**, please report it responsibly:

1. **Do not disclose the vulnerability publicly** in open GitHub Issues or public discussions until it has been reviewed and addressed.
2. Please use **[GitHub Private Vulnerability Reporting](https://github.com/jenilbanavani/whatstheplan/security/advisories/new)** to submit vulnerability details confidentially.
3. If private vulnerability reporting is unavailable, please open an issue requesting a private communication channel without exposing sensitive exploit details in the public description.

---

## 🔒 Security Best Practices for Contributors

- **Zero Secrets**: Never commit API keys, personal access tokens, keystores, or private credentials to the repository.
- **Privacy First**: The application is strictly offline. Pull requests that introduce remote networking, external analytics SDKs, or unencrypted telemetry will not be accepted.
- **Log Hygiene**: When posting bug reports or logcat snippets, ensure that personal file paths, device identifiers, and private user notes are redacted.
